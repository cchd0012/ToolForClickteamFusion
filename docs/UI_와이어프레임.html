툴 화면 와이어프레임

ToolForClickteamFusion을 디버거처럼 쓰는 화면 구조 제안입니다. 아래 화면은 눌러 볼 수 있고, 데이터는 예시입니다. 실제 값이 아니라 이 도구가 지금까지 읽어 낸 정보의 모양을 보여 줍니다.

예시 게임
프로젝트보기도움말ToolForClickteamFusion

설계 원칙

단계가 항상 보입니다

왼쪽 목록에 지금 단계, 끝난 단계, 문제가 있는 단계를 색으로 표시합니다. 처음 쓰는 사람은 위에서 아래로 따라가면 됩니다.

상태를 알려 줍니다

위쪽 줄에 진단 결과와 "재합성이 필요한 변경 수"를 배지로 둡니다. 편집기에서 저장하고 돌아오면 창이 포커스를 받는 순간 바뀐 파일을 다시 읽고 배지를 갱신합니다.

문제는 한곳에 모읍니다

경고와 진단은 아래 "문제" 탭에 모읍니다. 항목을 누르면 해결하는 화면으로 이동합니다.

길을 안내하되 막지 않습니다

기본은 안내 순서입니다. 아는 사람은 단계를 직접 눌러 이동합니다. 청크 트리와 JSON 도구는 "고급"에 그대로 남깁니다.

모르는 것은 모른다고 씁니다

그림 속 글자, 계산식으로 만든 문자열은 판단하지 않고 "확인할 수 없음"으로 표시합니다. 틀린 분류보다 빈칸이 낫습니다.

원본은 건드리지 않습니다

재합성은 항상 새 파일로 만들고, 작업 폴더를 원본과 분리합니다.

지금 기능을 어디에 두나

단계들어가는 기능지금 위치
1. 진단구조 분석, 진행 방향 안내, 문제 목록새 기능
2. 추출전체 추출, 종류별 추출, 끝난 뒤 진단 권유메뉴 "1.추출"
3. 문구이벤트, 오브젝트, 블리터 처음 문자열 편집, 번역 반영 상태JSON 파일을 직접 열어 편집
4. 글꼴과 글자폰트 아틀라스, 글자 오브젝트 배정, 게임 모듈 패치"한글화 도구" 창의 가/나/다 탭
5. 이미지이미지 목록, 교체, 추가메뉴 "2.수정"
6. 재합성종류 선택, 필요한 항목 미리 체크, 새 파일 만들기메뉴 "3.교체(재합성)"
7. 확인프레임 배치도, 번역 글자 미리보기새 기능
고급청크 트리, 스크립트 디컴파일과 리컴파일, 텍스트 흐름 원본기존 화면 그대로

만드는 순서

  1. 껍데기
    왼쪽 단계 목록, 위쪽 상태 줄, 아래 문제/로그 패널. 기존 창은 그 안에서 그대로 열리고, 메뉴는 프로젝트/보기/도움말로 줄입니다. 옛 메뉴는 고급에 보존합니다.
  2. 진단
    구조 분석과 안내, text/diagnosis.json, 추출이 끝난 뒤의 권유 창.
  3. "한글화 도구"를 4단계로 이전
    별도 창을 없애고 하위 탭으로 옮깁니다.
  4. 인스펙터와 미리보기
    오른쪽 패널을 채웁니다. 선택한 오브젝트의 옵션 이름과 글자 미리보기가 들어갑니다.
  5. 프레임 배치도와 아틀라스 미리보기
    7단계와 4단계에 얹습니다. 배치도가 생기면 아틀라스 미리보기에 실제 배경을 붙입니다.

ImGui로 만들 때

고정 영역 배치로 시작

도킹 대신 BeginChild 네 개로 영역을 나눕니다. 구분선을 끌어 폭을 바꾸는 간단한 스플리터만 직접 만들면 됩니다.

아이콘은 직접 그립니다

지금 쓰는 GUI_Font.ttf에는 원 숫자와 화살표가 없습니다. 상태 점, 체크, 경고는 글자 대신 ImDrawList의 원과 선으로 그립니다.

만들어 둘 공용 부품

단계 목록 항목, 배지, 배지 달린 탭, 문제 줄. 전부 Selectable과 ImDrawList 위에 얇게 얹는 정도입니다.

교체하지 않는 이유

필요한 것은 위젯 몇 개뿐이라 라이브러리를 바꾸는 비용이 이득보다 큽니다. 개조로 충분합니다.
