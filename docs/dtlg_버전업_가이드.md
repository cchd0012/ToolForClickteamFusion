# DustTale: Last Genocide 한글패치 버전업 가이드

게임이 새 버전으로 올라갔을 때, 이전 버전 한글판(1.0.5)의 번역·폰트·이미지를 새 버전(1.1.0)에 옮기는 방법과, 2페이즈에서 멈추던 원인이다. 스크립트는 `docs/dtlg/`에 있다.

이 게임은 글자를 윈도우 글꼴(Text 오브젝트)로 그린다. dtge와 달리 글자 이미지, 파서 모듈, 텍스트 블리터가 없어서 일반 한글화 흐름(문구, 폰트, 이미지)만 쓴다. 코드페이지는 949, 로케일은 1042로 바꾼다.

## 멈춤의 원인 (1.0.5 한글판 2페이즈)

`whatever limit you want to break so badly, kiddo...` 말풍선에서 게임이 멈췄다. 이 게임의 대사는 아래 두 곳이 같은 문자열이어야 다음으로 넘어간다.

| 위치 | 하는 일 |
|---|---|
| 동작 (줄 1050) | 말풍선 글자(`bubble text`)를 이 대사로 정한다 |
| 조건 (줄 754) | `bubble string`이 이 대사와 같고 Z키를 눌렀을 때 다음 대사로 넘어간다 |

1.0.5 한글판에서는 동작이 `네가 그토록 간절히 깨고 싶은 한계가 있다면...`, 조건이 `네가 그토록 간절히 부수고픈 한계가 있다면...`으로 서로 다르게 번역되어 있었다. 조건이 영원히 거짓이라서 Z를 눌러도 넘어가지 않았다. 게임 창을 직접 닫을 수밖에 없는 상태가 된 것이다.

같은 종류의 어긋남이 `* Sans - ??? ATK ??? DEF\r\n* His time is up.`(프레임 13 줄 695)에도 하나 더 있었다.

**재발 방지:** 번역은 `text/frameEventText.json`에서 원문 문자열 하나에 번역 하나로 정한다. 이 도구는 같은 원문을 어디서나 같은 번역으로 바꾸기 때문에 동작과 조건이 어긋날 수 없다. 이벤트 JSON에서 문자열을 곳곳마다 따로 고치지 않는다.

## 게임이 스스로 꺼지는 곳 (정상)

2페이즈가 끝나면 지지직 거리는 화면과 윙딩 문자가 나온 뒤 게임이 꺼진다. 프레임 14(`phase 2 ending glitch`)의 `crash` 이벤트가 "응용 프로그램 종료"를 실행하는 연출이다. 영어 원본에도 있다. 다시 실행하면 이어진다.

## 순서

폴더 규칙: 새 버전은 `v110/dtlg110.exe`와 그 추출 폴더 `v110/dtlg110/`, 이전 한글판은 `v105k/dtlg105k.exe`와 `v105k/dtlg105k/`로 둔다. (Git Bash에서는 `dtlg110`이 `dtlg110.exe`로 해석되므로 폴더 복사는 PowerShell로 한다.)

```bash
# 1. 두 exe 를 같은 방식으로 추출 (스크립트와 문구, 이미지, 폰트)
ToolForClickteamFusion.exe --extract v110/dtlg110.exe font blobs image script text module flow
ToolForClickteamFusion.exe --extract v105k/dtlg105k.exe font blobs image script text module flow

# 2. 한글판 문자열을 새 영어 문자열에 짝짓는다 (프레임별 순서 정렬) -> align_text.json
python align_text.py

# 3. 번역, 폰트, 이미지를 새 추출 폴더에 옮긴다 (DTLG_EX_FONT 는 이전 작업의 ex_font 폴더)
DTLG_EX_FONT=<ex_font> python build_ko.py <작업 폴더>
DTLG_EX_FONT=<ex_font> python make_ko_images.py <작업 폴더>     # 새로 생긴 영어 글자 그림의 한글 초안

# 4. 재합성
ToolForClickteamFusion.exe --replace dtlg110.exe font image text script codepage=949 locale=1042
```

`build_ko.py`가 하는 일:

- **문구:** 한글이 들어 있는 짝만 옮긴다. 영어끼리 다른 것(영어 원문이 바뀐 것)은 새 영어를 쓴다.
- **위치별 보정:** 같은 문자열이라도 곳마다 다르게 둔 것(크레딧의 `by ` / `| `, 이름 SOUP의 반응)은 이벤트 JSON에서 그 위치만 고친다.
- **오브젝트 문구:** 오브젝트 번호가 버전마다 달라서 이름 순서로 짝짓는다.
- **폰트:** 옛 영문 TTF의 내용 해시로 어떤 한글 폰트와 짝인지 찾는다. 오브젝트의 글꼴 이름은 그대로 두고 charset을 129로 바꾼다.
- **이미지:** 한글판에서 한글로 바꾼 이미지를 새 버전의 같은 이미지에 덮어쓴다. 핸들이 바뀐 것은 눈으로 확인해서 `IMG_MAP`에 적어 둔다.

## 점검 스크립트 (재합성한 exe를 다시 추출해서 돌린다)

| 스크립트 | 찾는 것 |
|---|---|
| `mismatch.py <추출 폴더>` | 비교 조건에 쓰인 문자열이 같은 프레임의 어떤 "텍스트 설정" 동작에서도 설정되지 않는 곳. 위의 멈춤 원인을 찾는다. 영어 원본에도 남는 것(이름 입력의 이스터에그, 한 줄 접두 비교)은 정상이다 |
| `prefixcheck.py <작업 폴더>` | 대사의 앞부분만 비교하는 조건이 번역 뒤에도 맞는지 |
| `dupall.py` | 번역하다가 서로 다른 두 대사가 같은 한글이 되어 한 번의 Z키로 둘 다 실행되는 곳 (대사 건너뛰기). 새 한글판은 0건이다 |
| `loops.py <추출 폴더>` | 지연 없이 스스로를 다시 부르는 루프 (무한 반복으로 멈출 수 있는 곳). 1.1.0은 프레임 10에 하나 있고 영어 원본과 같다 |

## 게임에서 확인하는 법

- `make_debug.py <추출 폴더> <이동 값> [--nodamage 프레임:uid,uid;...]`: 시작하자마자 특정 장면으로 이동하고 HP가 줄지 않게 한 시험용 빌드를 만든다. 이동 값은 프레임 번호가 아니라 프레임 이동 값이다 (`PHASE 2` = 5, `PHASE 3` = 12, `PHASE 3.5` = 26, `PHASE 4` = 27). 이동 값을 원래대로(15) 두면 정상 흐름으로 시작한다.
- `run_game.ps1 -Exe <exe> -OutDir <폴더> -Keys "6:z;9:z" -Seconds 540`: 게임을 띄워 키를 보내고 창을 캡처한다. 스스로 꺼지면 종료 코드를 로그에 남긴다.
- 게임은 `%APPDATA%\MMFApplications\save`에 진행 상황을 저장한다. 시험은 이 파일을 바꾸므로 시험 전에 복사해 둔다.
- 시험용 빌드는 배포하지 않는다. 배포용은 `--nodamage`와 이동 값을 쓰지 않은 빌드이다.

## 1.1.0에서 직접 확인이 필요한 것

- `* Nice moves, partner...`, `* But we have some work to do.`, `no hit`, `no heal`, `no item`, `no hit: on/off`, ` left`: 1.0.5 한글판에 없던 문구라서 초안 번역이다.
- 새로 생긴 영어 글자 그림(조작 안내 2장, 일기/성과 알림 4장)은 `make_ko_images.py`가 한글판 글꼴로 다시 그린 초안이다. 이전 이미지와 느낌이 다를 수 있다.
- 새 홍보 이미지(`dtge banner`, 640x480)와 일부 이름 입력 이스터에그 응답은 번역하지 않았다.
