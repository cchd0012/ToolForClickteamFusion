# ToolForClickteamFusion 사용 가이드

Clickteam Fusion으로 만든 게임(exe / dat / ccn)을 **한글화하기 위한 도구**다. 게임 파일 안의 문구, 이미지, 글꼴, 이벤트를 꺼내서(추출) 고치고 다시 합친다(재합성). 원본은 건드리지 않고 `<이름>_new` 파일을 새로 만든다.

이 문서는 버전 1.1.0 기준이며, 처음 쓰는 사람을 위한 전체 안내다. 자세한 내용은 맨 아래 [문서 목록](#문서-목록)의 문서를 본다.

## 1. 준비물

도구는 설치하지 않는다. 압축을 풀어 아무 폴더에 두고 `ToolForClickteamFusion.exe`를 실행하면 된다. 64비트 Windows 10 / 11이 필요하다.

배포 폴더에 들어 있는 것:

| 파일 | 뜻 |
|---|---|
| `ToolForClickteamFusion.exe` | 도구 본체 |
| `GUI_Font.ttf` | 도구 화면에 쓰는 한글 글꼴. exe와 **같은 폴더**에 둔다. 없으면 윈도우의 맑은 고딕(`malgun.ttf`)으로 대신한다 |
| `d3dx9_43.dll` | 화면을 그리는 DirectX 9 보조 라이브러리. 도구 화면이 안 뜨면 이 파일이 exe 옆에 있는지 본다 |
| `msvcp140.dll`, `vcruntime140.dll`, `vcruntime140_1.dll` | Visual C++ 실행 라이브러리 (PC에 이미 있으면 안 써도 된다) |
| `docs/` | 이 가이드를 포함한 문서 (HTML) |

한글화에 필요하지만 도구에 들어 있지 않은 것:

- **번역할 게임 파일.** 도구는 게임을 주지 않는다.
- **게임 글꼴이 한글을 갖고 있지 않을 때 쓸 한글 폰트** (`.ttf` / `.otf`, 또는 BMFont `.fnt`). 게임이 글자를 그림으로 그리는 방식이면 이 폰트로 한글 글자 그림(폰트 아틀라스)을 만든다. 폰트는 라이선스를 확인하고 고른다.
- **번역문.** 도구는 번역해 주지 않는다. `text/frameEventText.json`의 `translation`에 직접 채운다.

게임 실행 확인용으로, 한글이 나오려면 아카이브의 코드페이지가 949여야 한다. 아카이브를 연 뒤 `진단` 화면 맨 위의 `프로젝트 정보`에 `한국어 코드페이지로 변경`, `한국어 로케일로 변경` 단추가 있다 (저장할 때 반영된다).

## 2. 가장 짧은 흐름

1. `ToolForClickteamFusion.exe`를 실행하고 위쪽 메뉴 `프로젝트` → `열기`로 게임 파일(exe / dat / ccn)을 연다.
2. 왼쪽 단계 목록의 `추출`에서 `전체 추출`을 한다. 게임 파일 옆에 `<게임 이름>/` 폴더가 생긴다.
3. `진단`을 본다. 이 게임을 어떤 순서로 한글화하면 되는지, 문제가 될 만한 곳이 어디인지 알려 준다.
4. `문구`에서 번역할 파일(`text/frameEventText.json`, `text/objectText.json`)을 열어 `translation`을 채운다.
5. 게임이 글자를 그림으로 그리면 `글꼴·글자`에서 폰트 아틀라스를 만들고 글자 오브젝트에 적용한다. 그림 속 글자는 `이미지`에서 PNG를 바꾼다.
6. `재합성`에서 고친 것을 골라 새 파일(`<이름>_new`)로 저장한다.
7. 새 파일로 게임을 실행한다. 글자 위치가 궁금하면 도구의 `확인`(프레임 배치도)에서 미리 볼 수 있다.

고치고 다시 해 보는 일을 반복하게 된다. 편집기에서 JSON이나 PNG를 고치고 도구로 돌아오면 바뀐 파일을 자동으로 다시 읽는다 (위쪽의 `새로고침`을 눌러도 된다).

## 3. 화면 구성

- 맨 위 메뉴: `프로젝트`(열기, 저장), `보기`, `고급 도구`, `도움말`
- 왼쪽: 단계 목록. 위에서 아래로 진행하면 된다.
- 가운데: 고른 단계의 작업 화면
- 아래: 문제 / 로그 패널. 도구가 한 일과 경고가 쌓인다. 막혔을 때 먼저 본다.

| 단계 | 하는 일 |
|---|---|
| 진단 | 아카이브 구조를 분석해 한글화 진행 방향을 안내한다 |
| 추출 | 데이터를 파일(PNG, JSON 등)로 꺼낸다 |
| 문구 | 번역할 문자열 파일을 연다 |
| 글꼴·글자 | 한글 폰트 아틀라스를 만들고 글자 오브젝트와 게임 모듈에 적용한다 |
| 이미지 | 이미지를 고치거나 추가한다 |
| 재합성 | 고친 파일을 아카이브에 합쳐 새 파일로 저장한다 |
| 확인 | 프레임에 오브젝트가 놓인 모습을 본다 (처음 배치. 이벤트는 실행하지 않는다) |

`고급 도구`에는 같은 기능을 메뉴로 쓰는 `1.추출`, `2.수정`, `3.교체`가 있고, 아래 고급 화면도 `보기` 메뉴에서 연다.

| 고급 화면 | 하는 일 |
|---|---|
| 청크 트리 | 아카이브의 청크 구조를 본다 |
| 스크립트 JSON | 디컴파일한 이벤트와 오브젝트 JSON을 고치고 리컴파일한다 |
| 이벤트 찾기 | 이벤트에서 오브젝트나 동작을 찾는다. 찾은 동작이 무슨 일을 하는지 안내하고, 식을 숫자로 바꿔 고칠 수도 있다 |

## 4. 무엇을 할 수 있나

- **문구 번역:** 이벤트의 문자열, 오브젝트의 문자열, Text 문단을 원문 / 번역 쌍으로 꺼내 번역을 적용한다.
- **글자 그림(텍스트 블리터) 한글화:** 이미지 글꼴로 글을 그리는 게임에 한글 폰트 아틀라스를 만들어 넣는다. 자동 줄바꿈, 정렬, 글자 폭 계산을 한글에 맞게 정한다.
- **이미지 교체와 추가:** PNG로 꺼내서 같은 이름으로 바꾸거나 새로 더한다. 옛 형식 게임의 16 / 24비트 그림도 색과 투명이 맞게 나온다.
- **글꼴(TrueType) 교체:** 게임 안의 글꼴을 한글 글꼴로 바꾼다.
- **이벤트와 오브젝트를 읽는 JSON으로 풀기 / 다시 합치기:** 고치지 않은 것은 합쳐도 내용이 바뀌지 않는다.
- **이벤트 찾기:** 예를 들어 플레이어 HP가 줄어드는 곳을 찾아 그 식을 0으로 바꿔 시험할 수 있다.
- **진단:** 지금 연 파일만 분석해서 어떤 문제가 있을 수 있는지, 다음에 무엇을 하면 되는지 알려 준다. 판단하지 못한 것은 "알 수 없음"으로 둔다.

## 5. 지금까지 확인한 것과 한계

직접 해 본 게임: PrototypeNCSAGE, Sally (Whisper of Soul), Sonic 3D in 2D, Lone Fungus (그림), dtge (DustTale: The Genocide's End). dtge는 [번역 가이드](dtge_번역_가이드.md)가 따로 있다.

아직 하지 못하거나 확인하지 못한 것:

- 그림 속 글자(제목 로고, 메뉴 그림)는 글꼴이 아니라 이미지다. `이미지`에서 PNG를 직접 고친다.
- 글자 출력 모드(물결, 회전 등)를 쓰는 텍스트 블리터는 지원하지 않는다.
- 15비트 그림은 아직 지원하지 않는다 (해당 게임을 만나면 추가한다).
- `확인` 화면은 처음 배치다. 이벤트가 만들거나 옮기는 오브젝트, 화면 전환 효과는 나오지 않는다. 빠른 배경(Quick Backdrop)의 채움은 아직 그리지 않는다.
- 이벤트 찾기에서 이름이 붙는 동작 / 조건 번호는 확인한 일부뿐이다. 모르는 번호는 이름을 지어내지 않고 번호와 쓰인 예만 보여 준다. 식 고치기는 식 전체를 숫자 하나로 바꾸는 것만 된다.
- 데이터가 여러 파일로 나뉜 게임은 파일마다 따로 열어서 추출·교체해야 한다. 이런 게임으로 끝까지 해 본 적은 아직 없다.
- 한 번에 많이 고치지 말고, 고친 뒤 게임에서 확인하는 일을 자주 한다. 원본은 항상 그대로 두므로 되돌릴 수 있다.

## 6. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 실행하면 바로 꺼지거나 `d3dx9_43.dll`이 없다고 나온다 | `d3dx9_43.dll`이 exe와 같은 폴더에 있는지 본다 |
| `VCRUNTIME140`, `MSVCP140`이 없다고 나온다 | 배포 폴더의 해당 `.dll` 3개가 exe 옆에 있는지 본다. 없으면 Microsoft의 Visual C++ 재배포 가능 패키지(x64)를 설치한다 |
| 도구 화면의 한글이 `?`로 보인다 | `GUI_Font.ttf`가 exe 옆에 있는지 본다. 없고 윈도우 글꼴 폴더에 맑은 고딕도 없으면 한글이 안 나온다 |
| 게임에서 한글이 `?` 또는 깨져 보인다 | 코드페이지가 949인지, 글꼴 아틀라스를 오브젝트에 적용했는지, 게임이 실행 중에 글꼴 이미지를 다시 불러오는지 (진단의 `확인 필요`) 본다. [작업 흐름](한글화_작업흐름.md)의 2-4 |
| 번역을 채웠는데 안 바뀐다 | 문자열은 **정확히 같은 것만** 바뀐다. `translation`이 비어 있지 않고 원문과 달라야 한다. `재합성`에서 `text`를 골랐는지도 본다 |
| 번역하니 게임이 깨진다 | 키 문자열(INI 키, 파일 경로 등)을 번역했을 수 있다. `text/textFlow.json`과 `이벤트 찾기`로 그 문자열이 어디에 쓰이는지 확인한다 |
| 고쳤는데 도구에 반영이 안 된다 | 위쪽의 `새로고침`을 누른다. 도구가 직접 쓴 파일은 바뀐 것으로 보지 않는다 |
| 아카이브를 열었는데 아무것도 못 한다 | 아래 로그 패널의 오류 줄을 본다. 도구가 모르는 형식이면 이유가 로그에 남는다 |

## 7. 폴더 구조

추출하면 게임 파일 옆에 이런 폴더가 생긴다 (자세한 설명은 [작업 흐름](한글화_작업흐름.md)의 폴더 구조).

```
<게임 이름>/
  text/        frameEventText.json, objectText.json, textFlow.json
  script/      frame/*.json, object/*.json, backup/ (이벤트 찾기에서 고칠 때 원본)
  image/ font/ modules/
  glyph/       build_<이름>.json, atlases.json, atlas/<이름>.{png,kft,json}, txtblt_patched.mfx
```

## 8. 명령줄

화면을 쓰지 않고 같은 일을 명령줄로도 할 수 있다.

```bash
ToolForClickteamFusion.exe --extract game.dat script text flow
ToolForClickteamFusion.exe --diagnose game.dat
ToolForClickteamFusion.exe --replace game.dat codepage=949 locale=1042 script text
```
