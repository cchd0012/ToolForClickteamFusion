한글화 작업 흐름

Clickteam Fusion 게임(exe / dat / ccn)을 한글화하는 전체 흐름이다. 도구의 메뉴 순서와 같다.

코드
아카이브 열기 → 1.추출 → 2.수정 → 3.교체 (재합성) → 새 아카이브(~_new) 저장 → 게임에서 확인

수정하는 것은 파일(JSON, PNG, 폰트)이다. 기능은 따로 만든 도구가 아니라 추출된 JSON을 고치는 방식으로 쓴다.

게임별 안내: dtge (DustTale: The Genocide's End) 번역 가이드

1. 추출

1.추출 메뉴 (명령줄: --extract <아카이브> [종류...]). 아카이브 옆에 <아카이브 이름>/ 폴더가 생긴다.

종류만들어지는 것용도
texttext/frameEventText.json, text/objectText.json이벤트의 문자열, 오브젝트의 알터러블 문자열과 Text 문단 번역
scriptscript/frame/*.json, script/object/*.json이벤트와 오브젝트를 읽을 수 있는 JSON 으로 (오브젝트 속성, 블리터 설정 포함)
flowtext/textFlow.json텍스트 블리터가 받는 문구의 출처 분석 (추출만 가능)
image / font / moduleimage/, font/, modules/이미지(PNG), 폰트, 확장 모듈(exe 게임)
  • 전체 추출에는 flow가 들어 있다. 한글화 도구의 "나. 오브젝트에 적용"이 script/object와 text/textFlow.json을 읽는다.
  • 번역이 필요한 문구가 어디서 오는지는 text/textFlow.json으로 확인한다 (상수 / 다른 오브젝트의 문자열 참조 / INI 조회 / 계산식으로 분류).
  • 같은 파일의 fontReload는 게임이 실행 중에 글꼴 이미지를 다시 불러오는지 알려 준다 (detected, 불러오는 동작 수와 프레임, 파일 이름). 한글화 도구의 "나. 오브젝트에 적용"에도 같은 내용이 표시된다. 자세한 대응은 2-4를 본다.

2. 수정

2.수정 메뉴에서 종류별 추출 폴더를 열 수 있다.

2-1. 텍스트 번역

  • text/frameEventText.json: 항목마다 original(원문)과 translation(번역)이 있다. translation이 비어 있지 않고 원문과 다를 때만 적용한다.
  • 문자열은 정확히 같은 것만 바뀐다. 같은 문자열이 여러 곳에 있으면 모두 같이 바뀐다.
  • 비교에 쓰이는 키 문자열(INI 키, 파일 경로 등)은 번역하면 게임이 깨질 수 있다. 어디에 쓰이는지는 textFlow.json과 script/frame에서 확인한다.
  • text/objectText.json: 오브젝트의 알터러블 문자열과 Text 문단. original이 현재 값과 같을 때만 translation을 적용한다.
  • 게임이 외부 파일에서 읽는 문구(예: Data/Text/database.ini)는 아카이브 밖이므로 직접 고친다. 파일의 인코딩은 게임이 읽는 방식에 맞춘다 (PrototypeNCSAGE의 INI++ 는 UTF-8).

2-2. 이미지와 폰트

  • image/의 PNG를 같은 이름으로 바꾸거나 appendImages.json으로 새 이미지를 추가한다.
  • font/의 TrueType 폰트를 바꾸고, logFontInfo.json에서 charset을 129(한글)로 맞춘다. 폰트 이름은 달라도 charset이 맞으면 동작한다.

2-3. 글자를 이미지로 그리는 오브젝트(텍스트 블리터) 한글화

게임이 이미지 글꼴(txtblt.mfx)로 글을 그린다면, 폰트에서 한글 글자 그림을 만들어 모듈에 심는다. 2.수정 > 폰트의 한글화 도구 창이 세 단계를 안내한다.

가. 폰트 아틀라스 만들기

  • 폰트 파일(.ttf/.otf), 글자 크기, 글자·외곽선 색을 고른다.
  • 포함할 글자 (명령줄 mode):
  • 기본 (hangul): 영문 + 한글 2350자 (KS X 1001). 대부분의 번역에 충분하다.
  • 전체 (extendedHangul): 한글 11172자. 용량이 크다.
  • 필요한 글자만 (limitedHangul): 번역문(text, script/object)과 extraChars에 쓰인 글자만. 가장 작다. 번역을 고치면 다시 만들어야 한다.
  • 결과는 glyph/atlas/<이름>.png, .kft, .json. 같은 설정으로 다시 만들 수 있도록 glyph/build_<이름>.json을 남긴다.
  • 쓸 폰트 아틀라스에 1 이상의 서로 다른 번호를 붙이고 저장한다 (glyph/atlases.json).
  • 글꼴 크기가 작으면 일부 글자가 뭉개진다. 크기와 폰트를 바꿔 미리보기로 확인한다.

나. 오브젝트에 적용

  • 글자 오브젝트(텍스트 블리터) 목록을 불러와 오브젝트마다 폰트 아틀라스 번호와 줄 폭 계산 방식을 정한다.
  • 줄 폭 계산 byte(원래 방식): 글자 수 x 칸 폭. 영문처럼 폭이 같은 글꼴용.
  • 줄 폭 계산 pixel(글자 폭 합산): 글자마다 실제 폭을 더한다. 한글에 맞고, 공백으로 폭을 맞출 필요가 없다. 자동 줄바꿈과 정렬(가운데/오른쪽)은 원본과 같은 규칙이다.
  • 선택한 오브젝트에 나올 수 있는 문구(textFlow.json의 texts)를 정한 폰트 아틀라스로 미리 볼 수 있다.
  • "파일에 저장"하면 script/object/*.json의 textBlitter.fontTable, textBlitter.layout이 바뀐다.
  • 오브젝트가 처음에 갖는 문자열은 textBlitter.text(CP949)로 고친다.

다. 게임에 넣기

  • 원본 txtblt.mfx(37376바이트 판)에 폰트 아틀라스를 심은 새 모듈을 만든다 (glyph/txtblt_patched.mfx).
  • 만든 모듈을 게임의 모듈과 바꾼다.
  • exe 게임: 추출 폴더의 modules/ 파일을 바꾸고 교체에서 모듈을 체크한다.
  • dat/ccn 게임: 게임 폴더의 외부 모듈 파일(예: Data/Modules/txtblt.mfx)을 직접 바꾼다.

2-4. 게임별로 확인할 것 (PrototypeNCSAGE에서 겪은 것)

  • 게임이 이렇게 하는지는 textFlow.json의 fontReload.detected로 알 수 있다 (NCSAGE는 25곳에서 /Data/Fonts/<글꼴 이름>.png를 불러오고 Sally는 없다). 동작 번호는 37376바이트판 txtblt.mfx 기준이고, 파일 이름이 계산식이면 이름은 일부만 나온다.
  • 게임이 실행 중에 글꼴 이미지를 다시 불러온다면(Data/Fonts/*.png + fonts.meta, 확장 동작 "파일에서 폰트 이미지 불러오기"), 원래는 블리터 이미지가 원본 PNG로 덮여 글자가 깨진다. 이 도구가 만든 모듈은 폰트 아틀라스가 연결된 블리터에서는 이 동작을 무시하므로, 아틀라스를 이미지 뱅크에 넣어 두면 된다.
  • 이미지 뱅크에 넣기: image/appendImages.json으로 아틀라스 PNG를 새 핸들로 추가하고, script/object/*.json의 textBlitter.imageHandle, imageWidth, imageHeight를 그 값으로 바꾼다. Data/Fonts와 fonts.meta는 원본 그대로 둔다 (줄 높이 YFontSize도 원래 값이 쓰인다).
  • 다른 방법: 그 PNG를 폰트 아틀라스 PNG로 바꾸고 fonts.meta의 이미지 크기를 맞춘다. 이 방법은 모듈의 무시 기능이 없어도 된다.
  • 글자별 이벤트 옵션(글자마다 이벤트를 보내는 블리터)을 쓰는 오브젝트도 글자표로 그려진다. 이 경우 글자별 이벤트는 더 오지 않는다 (NCSAGE는 사운드 테스트의 곡 정보 줄 1개가 이 경우였다. 이 처리가 없으면 한글화한 게임에서 그 줄만 깨져 나온다).
  • 어느 오브젝트가 쓰는지는 오브젝트 JSON의 textBlitter.flagNames(CHAR_EVENT)에 표시된다. 같은 값이 textBlitter.flags(숫자)이고, 숫자를 고치고 리컴파일하면 옵션이 바뀐다 (flagNames는 설명용이라 고쳐도 무시한다). 이름을 아는 옵션은 ESCAPE, WRAP, CRLF, CHAR_EVENT, BOX이고 나머지 비트는 0x4000처럼 16진수로 나온다.
  • textFlow.json의 charEvents는 이 옵션을 쓰는 블리터와, 그 블리터가 받는 이벤트(확장 조건)의 수(handlers)를 알려 준다. handlers가 0이면 켜져 있어도 받는 곳이 없어 한글화해도 잃는 것이 없다 (한정자로 건 조건은 세지 않는다).
  • 문자열 안의 탭 문자는 원본처럼 탭 칸까지 가로 위치만 옮긴다. 줄 폭을 잴 때는 원본처럼 한 칸으로 세므로 가운데/오른쪽 정렬이면 어긋날 수 있다. 출력 모드(물결, 회전 등)를 쓰는 블리터는 아직 지원하지 않는다 (NCSAGE에는 없다). 출력 모드 오브젝트는 아직 표시하지 않는다.
  • 런타임이 확장에 ANSI 문자열을 넘기므로 아카이브의 코드페이지가 949여야 한글이 전달된다 (교체 때 codepage=949 locale=1042).
  • 이미지로 된 글자(제목 로고, 메뉴 그림)는 글꼴이 아니라 이미지 수정 영역이다.

디컴파일과 리컴파일

이벤트와 오브젝트를 읽을 수 있는 JSON 으로 풀고 다시 합치는 기능이다. 화면에서는 스크립트라는 이름으로 나온다.

  • 디컴파일: 1.추출의 스크립트 (전체 추출에 포함). script/frame/*.json, script/object/*.json 이 만들어진다.
  • 리컴파일: 3.교체의 스크립트 (전체 교체에 포함). 고친 JSON 이 있는 프레임과 오브젝트만 다시 만든다.
  • 수정하지 않은 JSON 으로 리컴파일하면 내용이 바뀌지 않는다 (게임 데이터를 디코드한 결과가 같다).

3. 교체 (재합성)

3.교체 (재합성) 메뉴 (명령줄: --replace <아카이브> [종류...]). 추출 폴더의 파일을 아카이브에 합쳐 같은 위치에 <이름>_new.<확장자>로 저장한다.

  • 번역과 오브젝트 설정만 바꿨다면 text, script를 고른다. 글자 이미지나 모듈을 바꿨다면 image, module도 고른다.
  • script와 text를 함께 고르면 script를 먼저 적용하고 text의 번역을 적용한다.
  • 한글 코드페이지와 로케일은 GUI의 "아카이브 정보" 창에서 [한국어 로케일로 변경], [한국어 코드페이지로 변경] 버튼으로 바꾼다 (저장할 때 반영된다). 명령줄에서는 codepage=949 locale=1042를 같이 적는다.
  • 원본은 건드리지 않는다. 새 파일로 게임을 실행해 확인한다.

명령줄 대응

bash
# 1. 추출
ToolForClickteamFusion.exe --extract game.dat script text flow

# 2. 수정 (한글화 도구 대신 명령줄로 할 때)
ToolForClickteamFusion.exe --font-atlas build glyph/build_atlas1.json
ToolForClickteamFusion.exe --txtblt-font patch txtblt.mfx txtblt_patched.mfx glyph/atlases.json

# 3. 교체
ToolForClickteamFusion.exe --replace game.dat codepage=949 locale=1042 script text

GUI에서 바로 열기: ToolForClickteamFusion.exe --open <아카이브> [atlas] [blitter] [module] (한글화 도구를 해당 탭으로 연다).

폴더 구조

코드
<아카이브 이름>/
  text/        frameEventText.json, objectText.json, textFlow.json
  script/      frame/*.json, object/*.json
  image/ font/ modules/
  glyph/       build_<이름>.json, atlases.json, atlas/<이름>.{png,kft,json}, txtblt_patched.mfx

용어

용어뜻
폰트 아틀라스폰트에서 만든 글자 그림(PNG)과 글자별 위치·폭 정보(.kft)
아틀라스 번호 (fontTable)오브젝트가 쓸 폰트 아틀라스를 가리키는 1 이상의 번호
글자 오브젝트 (텍스트 블리터)이미지 글꼴로 글을 그리는 확장 오브젝트 (txtblt.mfx, 식별자 TLBT)
줄 폭 계산 (layout)자동 줄바꿈과 정렬을 위해 한 줄의 폭을 재는 방식: byte / pixel
텍스트 흐름글자 오브젝트가 받는 문구의 출처 목록 (textFlow.json)
