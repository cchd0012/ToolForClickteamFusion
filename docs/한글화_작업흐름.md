# 한글화 작업 흐름

Clickteam Fusion 게임(exe / dat / ccn)을 한글화하는 전체 흐름이다. 도구의 메뉴 순서와 같다.

```
아카이브 열기 → 1.추출 → 2.수정 → 3.교체 (재합성) → 새 아카이브(~_new) 저장 → 게임에서 확인

화면 왼쪽의 단계 목록(진단, 추출, 문구, 글꼴·글자, 이미지, 재합성, 확인)이 같은 순서다. 아래 설명의 `1.추출`, `2.수정`, `3.교체` 메뉴는 `고급 도구` 메뉴로 옮겼고, 같은 기능을 해당 단계 화면에서도 쓸 수 있다. 확인 단계는 프레임 배치도다 (화면 구조는 [UI_와이어프레임.html](UI_와이어프레임.html)).
```

수정하는 것은 파일(JSON, PNG, 폰트)이다. 기능은 따로 만든 도구가 아니라 추출된 JSON을 고치는 방식으로 쓴다.

게임별 안내: [dtge (DustTale: The Genocide's End) 번역 가이드](dtge_번역_가이드.md)

---

## 0. 진단

추출한 뒤 진단을 한 번 돌려 보면, 이 게임에서 한글화를 어떤 순서로 진행할지 알려 준다 (화면의 `진단` 단계, 명령줄 `--diagnose <아카이브>`). 전체 추출이 끝나면 진단을 권하는 창이 뜬다. 결과는 `text/diagnosis.json`으로도 남는다.

항목마다 상태가 있다.

| 상태 | 뜻 |
|---|---|
| 확인됨 | 문제 없음, 또는 해결 방법이 정해져 있음 |
| 확인 필요 | 특별한 대응이 필요함 (예: 게임이 실행 중에 글꼴을 다시 불러옴, 코드페이지가 949가 아님) |
| 알 수 없음 | 도구가 판단하지 못함. 추측해서 단정하지 않는다 |
| 정보 | 진행 상황 같은 참고 정보 |

진단이 보는 것: 아카이브 종류와 엔진, 추출한 종류, 글자를 그리는 방식(txtblt 모듈판), 글꼴 다시 불러오기, 글자별 이벤트, 글자표 배정 수, 이벤트 문자열 수와 해석하지 못한 문구, 코드페이지와 로케일.

데이터가 여러 파일로 나뉜 게임: 같은 폴더(와 그 아래 `Data`)에서 이 파일 말고 아카이브로 보이는 `.ccn`(맨 앞이 PAMU)과 `.dat`(맨 앞이 0x77777777) 파일을 찾아 "관련 아카이브"로 알려 주고, 서브 애플리케이션 오브젝트(식별자 `CCA `) 수도 센다. 다른 아카이브가 있으면 파일마다 따로 열어서 추출하고 교체해야 한다 (추출 폴더와 결과 파일 `_new`는 아카이브 이름별로 따로 생긴다). 진단은 지금 연 파일만 본다.

진단이 하지 못하는 것: 그림 속 글자는 항상 "알 수 없음"이다. 문자열이 대사인지 내부 키인지는 구분하지 않는다. 모르는 txtblt 판은 "알 수 없음"으로 남고, 계산식으로 만드는 문구의 내용은 알 수 없다. 외부 모듈(dat 게임)은 게임 폴더의 `Data/Modules`, `Extensions`에서 찾는다.

## 1. 추출

`1.추출` 메뉴 (명령줄: `--extract <아카이브> [종류...]`). 아카이브 옆에 `<아카이브 이름>/` 폴더가 생긴다.

| 종류 | 만들어지는 것 | 용도 |
|---|---|---|
| `text` | `text/frameEventText.json`, `text/objectText.json` | 이벤트의 문자열, 오브젝트의 알터러블 문자열과 Text 문단 번역 |
| `script` | `script/frame/*.json`, `script/object/*.json` | 이벤트와 오브젝트를 읽을 수 있는 JSON 으로 (오브젝트 속성, 블리터 설정 포함) |
| `flow` | `text/textFlow.json` | 텍스트 블리터가 받는 문구의 출처 분석 (추출만 가능) |
| `image` / `font` / `module` | `image/`, `font/`, `modules/` | 이미지(PNG), 폰트, 확장 모듈(exe 게임) |

- 전체 추출에는 `flow`가 들어 있다. `글꼴·글자` 단계의 "나. 오브젝트에 적용"이 `script/object`와 `text/textFlow.json`을 읽는다.
- 번역이 필요한 문구가 어디서 오는지는 `text/textFlow.json`으로 확인한다 (상수 / 다른 오브젝트의 문자열 참조 / INI 조회 / 계산식으로 분류).
- 같은 파일의 `fontReload`는 게임이 실행 중에 글꼴 이미지를 다시 불러오는지 알려 준다 (`detected`, 불러오는 동작 수와 프레임, 파일 이름). `글꼴·글자` 단계의 "나. 오브젝트에 적용"에도 같은 내용이 표시된다. 자세한 대응은 2-4를 본다.

## 2. 수정

`2.수정` 메뉴에서 종류별 추출 폴더를 열 수 있다.

### 2-1. 텍스트 번역

- `text/frameEventText.json`: 항목마다 `original`(원문)과 `translation`(번역)이 있다. `translation`이 비어 있지 않고 원문과 다를 때만 적용한다.
  - 문자열은 **정확히 같은 것만** 바뀐다. 같은 문자열이 여러 곳에 있으면 모두 같이 바뀐다.
  - 비교에 쓰이는 키 문자열(INI 키, 파일 경로 등)은 번역하면 게임이 깨질 수 있다. 어디에 쓰이는지는 `textFlow.json`과 `script/frame`에서 확인한다.
- `text/objectText.json`: 오브젝트의 알터러블 문자열과 Text 문단. `original`이 현재 값과 같을 때만 `translation`을 적용한다.
- 게임이 외부 파일에서 읽는 문구(예: `Data/Text/database.ini`)는 아카이브 밖이므로 직접 고친다. 파일의 인코딩은 게임이 읽는 방식에 맞춘다 (PrototypeNCSAGE의 INI++ 는 UTF-8).

### 2-2. 이미지와 폰트

- `image/`의 PNG를 같은 이름으로 바꾸거나 `appendImages.json`으로 새 이미지를 추가한다.
- `font/`의 TrueType 폰트를 바꾸고, `logFontInfo.json`에서 charset을 129(한글)로 맞춘다. 폰트 이름은 달라도 charset이 맞으면 동작한다.

### 2-3. 글자를 이미지로 그리는 오브젝트(텍스트 블리터) 한글화

게임이 이미지 글꼴(txtblt.mfx)로 글을 그린다면, 폰트에서 한글 글자 그림을 만들어 모듈에 심는다. 화면의 `글꼴·글자` 단계(**한글화 도구**)가 세 단계를 안내한다.

**가. 폰트 아틀라스 만들기**

- 폰트 파일(.ttf/.otf), 글자 크기, 글자·외곽선 색을 고른다.
- 이미 만들어진 비트맵 폰트(BMFont)를 쓰려면 폰트 파일에 `.fnt`를 고른다. 글자 그림은 다시 그리지 않고 그대로 아틀라스 칸에 옮긴다.
  - 텍스트 또는 XML 형식 `.fnt`와 그 PNG 페이지(같은 폴더)가 필요하다. 이진 형식은 BMFont에서 텍스트나 XML로 다시 내보낸다.
  - 글자 크기, 글자 색, 외곽선, 세로 위치는 쓰이지 않는다. 글자 간격(모든 글자의 폭에 더하는 값)과 이미지 폭은 쓴다. 줄 높이는 `.fnt`의 `lineHeight`를 따른다.
  - 페이지 PNG의 알파가 전부 255(검은 바탕에 흰 글자)이면 밝기를 알파로 쓴다. 여러 페이지는 한 장으로 다시 모은다.
  - 유니코드 글자 중 CP949로 표현할 수 없는 것은 빠진다 (빠진 개수를 알려 준다). 글자마다 폭이 255, 가로 보정이 -128~127을 넘으면 그 한도로 맞춘다.
  - 설정 파일로는 `fontAtlas` 블록에 `font`와 `size` 대신 `"bmfont": "경로/글꼴.fnt"`를 쓴다.
- **간격 미리보기:** 폰트 파일을 정하면, 만들기 전에 폼의 값(글자 크기, 외곽선, 글자 간격, 세로 위치, 색)으로 미리보기 문구를 바로 그려 준다. 문구는 직접 고칠 수 있다 (번역한 문장을 넣어 보면 실제와 가깝다). 값을 바꾸면 곧바로 바뀐다. 이 미리보기는 문구에 쓰인 글자만 담은 작은 아틀라스를 메모리에서 만들 뿐 파일을 저장하지 않는다.
- 포함할 글자 (명령줄 `mode`):
  - 기본 (`hangul`): 영문 + 한글 2350자 (KS X 1001). 대부분의 번역에 충분하다.
  - 전체 (`extendedHangul`): 한글 11172자. 용량이 크다.
  - 필요한 글자만 (`limitedHangul`): 번역문(`text`, `script/object`)과 `extraChars`에 쓰인 글자만. 가장 작다. 번역을 고치면 다시 만들어야 한다.
- 결과는 `glyph/atlas/<이름>.png`, `.kft`, `.json`. 같은 설정으로 다시 만들 수 있도록 `glyph/build_<이름>.json`을 남긴다.
- 쓸 폰트 아틀라스에 1 이상의 서로 다른 **번호**를 붙이고 저장한다 (`glyph/atlases.json`).
- 글꼴 크기가 작으면 일부 글자가 뭉개진다. 크기와 폰트를 바꿔 미리보기로 확인한다.

**나. 오브젝트에 적용**

- 글자 오브젝트(텍스트 블리터) 목록을 불러와 오브젝트마다 폰트 아틀라스 번호와 줄 폭 계산 방식을 정한다.
  - 줄 폭 계산 `byte`(원래 방식): 글자 수 x 칸 폭. 영문처럼 폭이 같은 글꼴용.
  - 줄 폭 계산 `pixel`(글자 폭 합산): 글자마다 실제 폭을 더한다. 한글에 맞고, 공백으로 폭을 맞출 필요가 없다. 자동 줄바꿈과 정렬(가운데/오른쪽)은 원본과 같은 규칙이다.
- 목록에서 오브젝트를 고르면 오른쪽 패널에 인스펙터(오브젝트 번호, 원래 글꼴, 폰트 아틀라스, 줄 폭 계산, 칸 크기, 이미지 핸들, 옵션 이름)와 미리보기가 나온다. 미리보기는 그 오브젝트에 나올 수 있는 문구(`textFlow.json`의 `texts`)를 정한 폰트 아틀라스로 그린다. 옵션 이름의 뜻은 이름에 마우스를 올리면 나온다.
- "파일에 저장"하면 `script/object/*.json`의 `textBlitter.fontTable`, `textBlitter.layout`이 바뀐다.
- 오브젝트가 처음에 갖는 문자열은 `textBlitter.text`(CP949)로 고친다.

**다. 게임에 넣기**

- 원본 `txtblt.mfx`(37376바이트 판)에 폰트 아틀라스를 심은 새 모듈을 만든다 (`glyph/txtblt_patched.mfx`).
- 만든 모듈을 게임의 모듈과 바꾼다.
  - exe 게임: 추출 폴더의 `modules/` 파일을 바꾸고 교체에서 `모듈`을 체크한다.
  - dat/ccn 게임: 게임 폴더의 외부 모듈 파일(예: `Data/Modules/txtblt.mfx`)을 직접 바꾼다.

### 2-4. 게임별로 확인할 것 (PrototypeNCSAGE에서 겪은 것)

- 게임이 이렇게 하는지는 `textFlow.json`의 `fontReload.detected`로 알 수 있다 (NCSAGE는 25곳에서 `/Data/Fonts/<글꼴 이름>.png`를 불러오고 Sally는 없다). 동작 번호는 37376바이트판 txtblt.mfx 기준이고, 파일 이름이 계산식이면 이름은 일부만 나온다.
- 게임이 실행 중에 글꼴 이미지를 다시 불러온다면(`Data/Fonts/*.png` + `fonts.meta`, 확장 동작 "파일에서 폰트 이미지 불러오기"), 원래는 블리터 이미지가 원본 PNG로 덮여 글자가 깨진다. 이 도구가 만든 모듈은 폰트 아틀라스가 연결된 블리터에서는 이 동작을 무시하므로, 아틀라스를 이미지 뱅크에 넣어 두면 된다.
  - 이미지 뱅크에 넣기: `image/appendImages.json`으로 아틀라스 PNG를 새 핸들로 추가하고, `script/object/*.json`의 `textBlitter.imageHandle`, `imageWidth`, `imageHeight`를 그 값으로 바꾼다. `Data/Fonts`와 `fonts.meta`는 원본 그대로 둔다 (줄 높이 `YFontSize`도 원래 값이 쓰인다).
  - 다른 방법: 그 PNG를 폰트 아틀라스 PNG로 바꾸고 `fonts.meta`의 이미지 크기를 맞춘다. 이 방법은 모듈의 무시 기능이 없어도 된다.
- 글자별 이벤트 옵션(글자마다 이벤트를 보내는 블리터)을 쓰는 오브젝트도 글자표로 그려진다. 이 경우 글자별 이벤트는 더 오지 않는다 (NCSAGE는 사운드 테스트의 곡 정보 줄 1개가 이 경우였다. 이 처리가 없으면 한글화한 게임에서 그 줄만 깨져 나온다).
  - 어느 오브젝트가 쓰는지는 오브젝트 JSON의 `textBlitter.flagNames`(`CHAR_EVENT`)에 표시된다. 같은 값이 `textBlitter.flags`(숫자)이고, 숫자를 고치고 리컴파일하면 옵션이 바뀐다 (`flagNames`는 설명용이라 고쳐도 무시한다). 이름을 아는 옵션은 `ESCAPE`, `WRAP`, `CRLF`, `CHAR_EVENT`, `BOX`이고 나머지 비트는 `0x4000`처럼 16진수로 나온다.
  - `textFlow.json`의 `charEvents`는 이 옵션을 쓰는 블리터와, 그 블리터가 받는 이벤트(확장 조건)의 수(`handlers`)를 알려 준다. `handlers`가 0이면 켜져 있어도 받는 곳이 없어 한글화해도 잃는 것이 없다 (한정자로 건 조건은 세지 않는다).
- 문자열 안의 탭 문자는 원본처럼 탭 칸까지 가로 위치만 옮긴다. 줄 폭을 잴 때는 원본처럼 한 칸으로 세므로 가운데/오른쪽 정렬이면 어긋날 수 있다. 출력 모드(물결, 회전 등)를 쓰는 블리터는 아직 지원하지 않는다 (NCSAGE에는 없다). 출력 모드 오브젝트는 아직 표시하지 않는다.
- 오래된 Fusion으로 만든 게임(오브젝트가 `0x2229` 청크에 든 형식, 예: Sonic 3D 2D)도 오브젝트 JSON과 텍스트 흐름이 만들어진다. 이 형식에는 오브젝트 목록의 순서가 없어서 파일 이름(`script/object/000084.json`)과 `objectText.json`의 번호가 오브젝트의 핸들 번호다. 이벤트의 오브젝트 이름도 이 청크에서 가져온다.
- 런타임이 확장에 ANSI 문자열을 넘기므로 아카이브의 코드페이지가 949여야 한글이 전달된다 (교체 때 `codepage=949 locale=1042`).
- 이미지로 된 글자(제목 로고, 메뉴 그림)는 글꼴이 아니라 이미지 수정 영역이다.

## 확인 (프레임 배치도)

화면의 `확인` 단계에서 프레임을 고르면 오브젝트가 놓인 모습을 보여 준다. 추출한 `script`와 `image` 폴더만 읽는다 (프레임 JSON의 `layout`, 오브젝트 JSON, `image/imageList.json`과 PNG).

- 마우스 휠로 확대·축소(25%~800%, 가리킨 곳을 중심으로)하고, 끌어서 화면을 옮긴다 (가운데 버튼도 된다). `배율`에서 `맞춤`을 고르면 처음 위치로 돌아온다. 스테이지 프레임처럼 큰 프레임은 `맞춤`이 0.2배까지만 줄이므로 나머지는 끌어서 본다.
- 프레임 크기, 배경색, 오브젝트 위치대로 활성 오브젝트(스프라이트)는 첫 애니메이션의 첫 그림으로, 글자 오브젝트는 처음 문자열로, 크기를 모르는 오브젝트는 작은 표식으로 그린다. 오브젝트를 누르면 오른쪽 패널에 상세가 나오고, `이 오브젝트 숨기기`로 가릴 수 있다.
- **처음 배치다.** 이벤트는 실행하지 않아서, 이벤트가 만들거나 옮기거나 보이게 하는 오브젝트와 화면 전환 효과는 반영되지 않는다. 맨 위에 그려지는 전체 화면 그림(페이드 덮개)은 기본으로 숨긴다 (`덮개 숨김`).
- 글자 오브젝트에 폰트 아틀라스가 배정되어 있으면 그 아틀라스 글자로 그린다 (`폰트 아틀라스 글자`). 번역한 문구를 `글꼴·글자` 단계에서 배정한 뒤 이 화면에서 한글이 어떻게 보이는지 확인할 수 있다. 글자 오브젝트의 줄 폭(이미지 폭), 자동 줄바꿈(`WRAP`), 정렬(왼쪽, 가운데, 오른쪽)과 줄 폭 계산 방식(글자 폭 합산 또는 글자 수 x 칸 폭)을 게임과 같은 규칙으로 따라 한다. 다만 게임 안의 계산을 그대로 옮긴 것은 아니라서, 줄 끝의 공백이나 탭 문자, 여러 줄 정렬의 미세한 차이는 어긋날 수 있다. 아틀라스가 없는 오브젝트는 도구의 글꼴로 대신 그리고, 정렬만 반영한다. 오른쪽 패널에는 줄 폭과 정렬이 나온다. 오브젝트 JSON의 `textBlitter.align`(0 왼쪽, 1 가운데, 2 오른쪽)과 `tabWidth`는 보기 전용이다.
- 배경 오브젝트(Backdrop)는 `script/backdrops.json`(스크립트 추출 때 같이 만들어진다. 크기, 그림 번호, 장애물/충돌 종류)을 읽어 그림 크기대로 놓인 위치에 그린다. 이 파일이 없으면(이전 버전으로 추출한 경우) 스크립트를 다시 추출한다. 빠른 배경(Quick Backdrop)은 색이나 무늬 채움을 아직 해석하지 못해 크기만 윤곽선으로 보인다. `backdrops.json`은 보기 전용이라 재합성에는 쓰이지 않는다. 옛 형식(0x2229)도 같은 구조라 같이 만들어진다.
- 그림은 `image/imageList.json`(이미지 추출 때 같이 만들어진다)이 있어야 그린다. 옛 형식(0x2229, Sonic 3D)도 이제 목록이 만들어져 그려진다.
- 프레임 JSON의 `layout`은 보기 전용이다. 고쳐도 재합성에 쓰이지 않는다.

## 바뀐 파일 다시 읽기

번역하는 동안에는 도구 옆에서 편집기로 JSON이나 PNG를 고치고 도구로 돌아오는 일이 많다. 도구는 읽어 둔 추출 폴더의 파일을 기억해 두고(수정 시각과 크기), 아래 때에 달라진 파일만 다시 읽는다.

- 창으로 돌아올 때 (자동)
- 위쪽 줄의 `새로고침`을 눌렀을 때
- 단계를 옮길 때 (바뀐 게 없으면 조용히 지나간다)

무엇을 다시 읽는지:

| 화면 | 지켜보는 파일 | 바뀌면 |
|---|---|---|
| 확인 | `script/frame`, `script/object`, `image` | 바뀐 프레임 배치, 오브젝트 정보, 그림만 다시 읽는다. 프레임 파일이 늘거나 줄거나 `imageList.json`이 바뀌면 처음부터 읽되 보던 프레임과 고른 오브젝트는 유지한다 |
| 글꼴·글자 | `script/object`(글자 오브젝트), `text/textFlow.json`, `glyph/atlas`, `glyph/atlases.json` | 글자 오브젝트 목록, 아틀라스 목록과 미리보기를 다시 읽는다 |

- 자동으로 시작했을 때는 바뀐 내용이 0.35초 뒤에도 같을 때 적용한다. 편집기가 파일을 쓰는 도중에 읽지 않기 위해서다. `새로고침`은 기다리지 않고 바로 적용한다.
- 저장하지 않은 폰트 아틀라스 지정이 있으면 글자 오브젝트 목록은 다시 읽지 않고 로그에 알린다 (지정을 잃지 않기 위해서다). 아틀라스 번호를 고르고 아직 `번호 저장`을 하지 않은 것도 유지한다.
- 도구가 직접 쓴 파일(저장, 아틀라스 만들기)은 바뀐 것으로 보지 않는다.
- 다시 읽은 내용은 아래 로그 탭에 남는다.

## 디컴파일과 리컴파일

이벤트와 오브젝트를 읽을 수 있는 JSON 으로 풀고 다시 합치는 기능이다. 화면에서는 `스크립트`라는 이름으로 나온다.

- 디컴파일: `1.추출`의 `스크립트` (전체 추출에 포함). `script/frame/*.json`, `script/object/*.json` 이 만들어진다.
- 리컴파일: `3.교체`의 `스크립트` (전체 교체에 포함). 고친 JSON 이 있는 프레임과 오브젝트만 다시 만든다.
- 수정하지 않은 JSON 으로 리컴파일하면 내용이 바뀌지 않는다 (게임 데이터를 디코드한 결과가 같다).
- 이벤트 파라미터는 종류별 필드로 풀린다. 구조를 모르거나 다시 합쳤을 때 원본과 같지 않은 것만 `"kind": "raw"`(16진수)로 남는다. 코드 68(알터러블/전역 값 여러 개를 한꺼번에 정하는 `multiVariables`)과 코드 69(오브젝트 정보 목록 `childEvent`)도 풀린다. 예전 JSON 에 raw 로 적힌 이 두 코드는 그대로 리컴파일해도 같은 결과가 나온다.

## 이벤트 찾기

`고급`의 `이벤트 찾기`는 디컴파일한 이벤트(`script/frame/*.json`)에서 조건에 맞는 이벤트 그룹을 찾아 보여 준다. 게임 안의 어떤 동작이 어디서 일어나는지 알고 싶을 때(체력이 줄어드는 곳, 화면 이동, 특정 문구를 쓰는 곳 등) 쓴다. 먼저 `1.추출`에서 `스크립트`를 추출해 둬야 한다.

- 찾는 조건 (아는 것만 적고, 비워 둔 것은 따지지 않는다)
  - 오브젝트 이름: 일부만 맞아도 된다 (대소문자 구분 없음)
  - 번호: 동작 또는 조건 번호. 조건 번호는 음수이다 (예: `-81`)
  - 종류: 조건과 동작 / 조건만 / 동작만
  - 파라미터 글자: 파라미터의 식이나 값에 든 글자 (문자열 상수, 그룹 이름 찾기에 쓴다)
  - 프레임: 한 프레임만 훑는다
- **번호를 몰라도 고르기**: `이 게임에 쓰인 동작과 조건`을 펼치고 `목록 만들기`를 누르면, 모든 프레임을 훑어서 (조건/동작, 오브젝트 종류, 번호)마다 한 줄로 모은다 (dtge는 313종).
  - 줄마다 횟수, 그 번호를 쓴 오브젝트 이름 예(최대 4개), 처음 나온 이벤트의 파라미터 예가 나온다.
  - `목록 거르기`에 오브젝트 종류 이름(예: `카운터`), 번호, 오브젝트 이름, 파라미터 글자를 적으면 목록이 줄어든다.
  - 줄 끝의 `찾기`를 누르면 그 종류(오브젝트 종류와 번호, 조건/동작)로 고정해서 바로 찾는다. 위쪽에 `오브젝트 종류 고정`이 나오고 `해제`로 풀 수 있다.
  - 이 도구가 뜻을 확인한 번호는 이름(예: `#82 빼기`)이 붙고, 번호 칸에 마우스를 올리면 설명이 나온다. 확인하지 못한 번호는 이름을 지어내지 않고 번호와 쓰인 예만 보여 준다.
- 결과는 프레임 번호, 이벤트 줄, 그룹의 조건과 동작으로 나온다. 조건에 맞은 줄은 `>`와 노란색으로 표시한다. 한 번에 300개까지 보여 준다.
- 번호 뒤 괄호의 이름(값 비교, 빼기 등)은 이 도구가 데이터로 확인한 것만 붙는다: 카운터의 값 정하기/더하기/빼기/최소값/최대값/색(80~85)과 값 비교(-81), 알터러블 값 정하기(31)와 비교(-42), 프레임 이동(-3의 2). 그 밖의 번호는 번호만 나온다.
- 찾은 이벤트에 뜻을 아는 동작이 있으면 위에 안내가 나온다 (예: 카운터에서 빼는 동작이면 "체력이 줄어드는 곳일 수 있다, 시험하려면 식을 0으로 고친다").
- **바로 고치기**: 맞은 줄(`>`)에 식(expression) 파라미터가 있으면 줄 아래에 `파라미터 N 의 식: ...` 과 숫자 입력 칸, `숫자로 바꾸기`가 나온다. 누르면 그 식 전체가 입력한 숫자 하나로 바뀌어 프레임 JSON(`script/frame/<프레임 번호 6자리>.json`)에 저장된다.
  - 처음 고칠 때 원본 프레임 JSON을 `script/backup/`에 둔다 (이미 있으면 그대로 두어서 가장 처음 원본이 남는다). 되돌리려면 그 파일을 `script/frame/`에 덮어쓰거나 다시 추출한다.
  - 바뀌는 곳은 그 식의 글자와 토큰뿐이다 (dtge 프레임 14에서 비교해 확인했다). 식 전체를 숫자 하나로 바꾸는 것만 지원하고, 식의 일부만 고치는 것은 하지 않는다. 정수만 쓸 수 있다.
  - 게임에는 `3.교체`의 `스크립트`로 재합성해야 반영된다. 식이 짧아지면 뒤따르는 그룹 포인터 값이 달라지는데, 저장할 때 도구가 다시 계산하는 읽기용 값이다.
  - 조건이나 동작이 식 파라미터가 아닌 것(오브젝트, 위치, 소리 등)은 이 단추가 나오지 않는다. 그런 것은 프레임 JSON을 직접 고친다.
- dtge에서 `오브젝트 이름 HP`, `번호 82`로 찾으면 플레이어 HP를 깎는 동작 두 곳이 나온다 (`docs/dtge_번역_가이드.md`의 HP 시험 항목).

## 3. 교체 (재합성)

`3.교체 (재합성)` 메뉴 (명령줄: `--replace <아카이브> [종류...]`). 추출 폴더의 파일을 아카이브에 합쳐 같은 위치에 `<이름>_new.<확장자>`로 저장한다.

- 번역과 오브젝트 설정만 바꿨다면 `text`, `script`를 고른다. 글자 이미지나 모듈을 바꿨다면 `image`, `module`도 고른다.
- `script`와 `text`를 함께 고르면 `script`를 먼저 적용하고 `text`의 번역을 적용한다.
- 한글 코드페이지와 로케일은 GUI의 "아카이브 정보" 창에서 [한국어 로케일로 변경], [한국어 코드페이지로 변경] 버튼으로 바꾼다 (저장할 때 반영된다).
  명령줄에서는 `codepage=949 locale=1042`를 같이 적는다.
- 원본은 건드리지 않는다. 새 파일로 게임을 실행해 확인한다.

## 명령줄 대응

```bash
# 1. 추출
ToolForClickteamFusion.exe --extract game.dat script text flow

# 진단 (추출한 뒤)
ToolForClickteamFusion.exe --diagnose game.dat

# 2. 수정 (글꼴·글자 단계 대신 명령줄로 할 때)
ToolForClickteamFusion.exe --font-atlas build glyph/build_atlas1.json
ToolForClickteamFusion.exe --txtblt-font patch txtblt.mfx txtblt_patched.mfx glyph/atlases.json

# 3. 교체
ToolForClickteamFusion.exe --replace game.dat codepage=949 locale=1042 script text
```

GUI에서 바로 열기: `ToolForClickteamFusion.exe --open <아카이브> [atlas] [blitter] [module]` (`글꼴·글자` 단계의 해당 탭을 연다).

## 폴더 구조

```
<아카이브 이름>/
  text/        frameEventText.json, objectText.json, textFlow.json
  script/      frame/*.json, object/*.json
  image/ font/ modules/
  glyph/       build_<이름>.json, atlases.json, atlas/<이름>.{png,kft,json}, txtblt_patched.mfx
```

## 용어

| 용어 | 뜻 |
|---|---|
| 폰트 아틀라스 | 폰트에서 만든 글자 그림(PNG)과 글자별 위치·폭 정보(.kft) |
| 아틀라스 번호 (`fontTable`) | 오브젝트가 쓸 폰트 아틀라스를 가리키는 1 이상의 번호 |
| 글자 오브젝트 (텍스트 블리터) | 이미지 글꼴로 글을 그리는 확장 오브젝트 (`txtblt.mfx`, 식별자 `TLBT`) |
| 줄 폭 계산 (`layout`) | 자동 줄바꿈과 정렬을 위해 한 줄의 폭을 재는 방식: `byte` / `pixel` |
| 텍스트 흐름 | 글자 오브젝트가 받는 문구의 출처 목록 (`textFlow.json`) |
